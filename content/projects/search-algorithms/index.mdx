The Search Algorithms Visualizer shows how the classical AI search algorithms actually explore a problem. Pick an algorithm, press play, and watch the frontier grow, the explored set fill in, and the path come back, with the queue, stack, or priority queue shown live beside it. The frame above is the real thing running in the page.

## Three ways to look at a search

- **Grid.** A weighted pathfinding board. Draw walls, drag the start and goal, paint expensive terrain, or generate a maze. Race mode runs all eight algorithms side by side on the same board.
- **Graph.** A state-space graph with labelled nodes and weighted edges, including the Romania road map with real distances and a preset with a deliberately bad heuristic, so you can watch A* return a worse path.
- **Tree.** The search tree the algorithm really generates, growing as it expands. Depth-limited search draws its cutoff line here, and iterative deepening visibly wipes and redraws the tree one level deeper each round.

Every run also shows each node's g, h, and f values, a step-by-step trace, and the pseudocode.

## Decisions worth knowing

- **The conventions are switches, not choices made for you.** Textbooks disagree on when to test for the goal and whether to keep an explored set, and both change the answer. Testing on generation, for example, costs uniform-cost search and A* their optimality, and you can watch it happen.
- **A subtle bug, handled.** A depth-limited search with a naive explored set can miss a goal that is inside the limit. Here the explored set remembers the depth each state was expanded at and re-expands on a shallower arrival.
- **Verified against ground truth.** A Node harness checks every algorithm against Dijkstra across hundreds of random grids and graphs: optimal algorithms must find the optimal cost, A* must never expand more than uniform-cost, and every path must be valid.
- **The tests were tested.** Each class of assertion was confirmed to fail against a deliberately broken implementation, including the two easiest mistakes to miss in bidirectional search.
- **No build step.** Algorithms are generators that yield step events and the views only consume those events, so it runs straight from a file with plain scripts and no dependencies.
