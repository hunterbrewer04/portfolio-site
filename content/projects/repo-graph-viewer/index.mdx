Repo Graph Viewer turns the `graph.json` that [graphify](https://github.com/Graphify-Labs/graphify) extracts from a codebase into something you can actually explore. graphify parses a repo's AST into nodes (functions, classes, files) and links (calls, imports, definitions), then clusters them into communities. Its output is a JSON blob. This renders it as a live force-directed graph, in the browser, with nothing to install.

The frame above is the real app running against this portfolio's own graph. Pick another example from the header, or drop any `graph.json` onto it.

## What it does

- **Two renderers.** A 2D canvas for reading structure and a 3D WebGL view for the shape of a codebase. `G` toggles between them; 3D auto-rotates until you grab it.
- **Walk the graph.** Hovering a node highlights it and its neighbors and dims everything else. Clicking opens a detail panel with the node's kind, file, community, and every neighbor as a link, so you can step through a call chain one hop at a time.
- **Search.** Matches and their neighbors light up; `Esc` clears search and selection.
- **Edge semantics are visible.** Solid edges are `EXTRACTED` from the AST; dashed edges are `INFERRED`, graphify's guess. Colors come from a 16-hue community palette.
- **Bundled examples.** Five graphs from my own repos ship with the site and are fetched on click, not on load, so the initial page stays small.
- **Phone layout.** The detail panel becomes a bottom sheet, tapping a node pans it into the strip above the sheet, and the search field is 16px because iOS Safari zooms the page to focus anything smaller.

## Engineering details worth noting

- **The loader is defensive on purpose.** graphify is under active development and its format moves. Across the repos this was tested against, `type` was usually absent, `built_at_commit` was sometimes missing entirely, `links` and `edges` both appeared, and new relation names and unmodeled fields kept showing up. The loader reads every field with a fallback, drops links that point at nodes not in the set (react-force-graph throws on them), wraps community colors by `community % 16` when a repo clusters past the palette, and a unit test covers each variation so the next format change fails a test instead of the page.
- **react-force-graph mutates its input.** It writes `x`/`y`/`z` onto nodes and swaps each link's string `source`/`target` for a live node reference. So the graph object passed in is memoized, since a new one restarts the layout, and the adjacency index snapshots endpoint ids at build time rather than holding link references that will change under it.
- **Opacity is multiplicative in 3D.** The renderer multiplies `nodeOpacity` by the alpha of the node's color, which made dimming double-apply. Both opacity props are pinned to 1 so the rgba color is the single source of truth, and 3D dims less than 2D because its spheres are already Lambert-shaded.
- **Three.js stays out of the bundle until 3D opens.** The 2D and 3D renderers are imported as separate packages behind `next/dynamic` with `ssr: false`, rather than the `react-force-graph` umbrella, which also pulls in the AR/VR builds and throws `AFRAME is not defined` in dev.
- **Theme without a flash.** Light or dark is applied by an inline script in the document body before first paint, ahead of React. Only the chrome switches: the canvas stays black in both themes because the community palette is tuned for light-on-dark. A `?theme=` URL param wins for a single load, which is how this page embeds it dark without touching a visitor's saved choice.
- **A tripwire for the examples.** A test walks the example manifest and checks that every entry's file exists, parses through the loader, and matches the node, link, and community counts printed on its card. Regenerating a graph without updating the manifest fails the suite.

## Stack and deploy

Next.js App Router, React 19, and Tailwind v4 on the page; `react-force-graph-2d` and `react-force-graph-3d` (d3-force layout, Three.js for the WebGL view) for the graph; Vitest for the loader, adjacency, and example tests. There is no backend. `output: "export"` produces a plain static site and Cloudflare Pages builds it from the repo on every push.
